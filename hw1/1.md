```cpp
volatile std::nullptr_t a = nullptr; int *b; b = a;
```

Если скомпилировать следующий код на -O2, то GCC и Clang сгенерируют разный ассемблер.

По стандарту реализация обязана эмулировать наблюдаемое поведение абстрактной машины (as-if rule). 
В наблюдаемое поведение, помимо прочего входит доступ к volatile переменным [intro.abstract/8.1](https://eel.is/c++draft/intro.abstract#8.1):

> Accesses through volatile glvalues are evaluated strictly according to the rules of the abstract machine.

При присваивании b = a применяется lvalue to rvalue преобразование над a. 
Если glvalue имеет тип cv std::nullptr_t, результатом всегда является null pointer constant [conv.lval/3.1](https://eel.is/c++draft/conv.lval#3.1):

> If T is cv std​::​nullptr_t, the result is a null pointer constant
> [Note 1: Since the conversion does not access the object to which the glvalue refers, there is no side effect even if T is volatile-qualified ([intro.execution]), and the glvalue can refer to an inactive member of a union ([class.union]). — end note]

В заметке 1 поясняется: поскольку преобразование не читает объект, следовательно нет и побочного эффекта, несмотря на модификатор volatile.
Значит, можно считать, что в данном случае **прав clang**, а gcc добавил лишнее чтение.
