GCC здесь прав. Для каждой перегрузки нужна неявная последовательность преобразования из {{}, {}} в `Pair<X, X>`. Pair не агрегат, у него есть конструктор. По [over.ics.list](https://eel.is/c++draft/over.match#over.ics.list-7) последовательность строится через выбор конструктора по правилами [over.match.list]. Если конструктор найден, последовательность пользовательская.

Шаблонные аргументы конструктора берутся из значений по умолчанию: аргумент {} для параметра U1&& -- невыводимый контекст [temp.deduct.call/1](https://eel.is/c++draft/temp.deduct.call#1). Следовательно, для `f(Pair<E, E>)` конструктор принимает `E&&, E&&` и `S&&, S&&` для второй перегрузки.

Для `f(Pair<E, E>)` нужно привязать ссылку к временному E, созданному копирующей инициализацией из {}. Для пустого списка выбирается конструктор по умолчанию -- `explicit E()`.

> In copy-list-initialization, if an explicit constructor is chosen, the initialization is ill-formed.
> [Note 1: This differs from other situations ([over.match.ctor], [over.match.copy]), where only non-explicit constructors are considered for copy-initialization. This restriction only applies if this initialization is part of the final result of overload resolution. — end note]

Следовательно при копирующей списочной инициализации explicit конструкторы участвуют в выборе наравне с остальными. Ошибкой становится только если explicit выиграет перегрузку. Значит `f(Pair<E, E>)` -- жизнеспособный кандидат.

Получаем, что обе последовательности пользовательские и не сравниваются. По [over.ics.rank/3.3](https://eel.is/c++draft/over.ics.rank#3.3) две пользовательские последовательности различимы только если в них участвует одна и та же функция преобразования или конструктор. Здесь конструкторы разные `(Pair<E, E>::Pair, Pair<S, S>::Pair)`, поэтому ни одна перегрузка не лучше другой [over.match.best](https://eel.is/c++draft/over.match.best#general-3). Вызов неоднозначен, программа ill-formed.

Clang исключает кандидатов, у которых при копирующей списочной инициализации выбирается explicit конструктор.
